# Notes REST API — Assignment 6

An Express REST API for notes, using a **persistent MongoDB database** with Mongoose. No React frontend is needed. This implements the five required CRUD routes, validation, JSON errors, and database persistence.

## Requirements

- Node.js 20 or newer
- A MongoDB Atlas cluster (or a local MongoDB server)
- Postman, Thunder Client, or a terminal with curl

## Setup and running

1. Download or clone the repository and open the `notes-rest-api` folder in a terminal.
2. Run `npm install`.
3. Copy `.env.example` to `.env` (on Windows: `copy .env.example .env`; macOS/Linux: `cp .env.example .env`).
4. Set `MONGODB_URI` in `.env` to your working MongoDB connection string. For MongoDB Atlas: create a database user and allow your current IP in Network Access. Keep credentials private.
5. Run `npm run dev` (or `npm start`). The console should print **Connected to MongoDB** and the URL. The API listens on port 3000 unless `PORT` is changed.
6. Import `postman/Notes-REST-API.postman_collection.json` into Postman and execute the requests in order. Or use the curl commands below.

`.env` and `node_modules/` are intentionally ignored by Git. `.env.example` contains placeholders; replace them in your private `.env` file. **Never commit your real MongoDB password.**

To run automated HTTP tests: `npm test`. These tests mock Mongoose calls to test Express responses; **they are not a replacement for the manual MongoDB persistence test** described below.

## Data model

| Field | Type | Validation |
| --- | --- | --- |
| `_id` | ObjectId | MongoDB-generated |
| `title` | string | required, trimmed, nonempty, max 120 chars |
| `body` | string | optional; defaults to empty string |
| `tags` | string[] | optional; defaults to empty array |
| `createdAt`, `updatedAt` | date | auto-generated by Mongoose timestamps |

Clients may send only `title`, `body`, and `tags`; IDs and timestamps are server-managed.

## Routes

Base URL: `http://localhost:3000`

| Method | Route | Success | Purpose |
| --- | --- | --- | --- |
| GET | `/api/notes` | 200 | all notes, newest first |
| GET | `/api/notes?search=exam` | 200 | case-insensitive literal-title search |
| GET | `/api/notes/:id` | 200 | one note |
| POST | `/api/notes` | 201 | create note |
| PUT | `/api/notes/:id` | 200 | replace editable note fields |
| DELETE | `/api/notes/:id` | 204 | delete note; no body |

Example note response (the actual ID and timestamps are generated by MongoDB):

```json
{
  "_id": "507f1f77bcf86cd799439011",
  "title": "Study REST APIs",
  "body": "Practice Express routes",
  "tags": ["webdev", "exam"],
  "createdAt": "2026-11-08T10:00:00.000Z",
  "updatedAt": "2026-11-08T10:00:00.000Z",
  "__v": 0
}
```

### 1. List all — GET /api/notes

```bash
curl -i http://localhost:3000/api/notes
```

Response **200**: JSON array of note objects, or `[]` if none exist.

### 2. Get one — GET /api/notes/:id

```bash
curl -i http://localhost:3000/api/notes/REPLACE_WITH_REAL_ID
```

Response **200**: one note object like the example above. Missing note: **404** `{"error":"Note not found"}`. Invalid ID: **400** `{"error":"Invalid note ID"}`.

### 3. Create — POST /api/notes

```bash
curl -i -X POST http://localhost:3000/api/notes -H "Content-Type: application/json" -d '{"title":"Study REST APIs","body":"Practice Express routes","tags":["webdev","exam"]}'
```

Response **201**: the created note object, with its generated `_id` and timestamps.

Invalid example: request body `{"body":"Missing a title"}` returns **400**:

```json
{"error":"title is required and must be a nonempty string"}
```

### 4. Replace — PUT /api/notes/:id

```bash
curl -i -X PUT http://localhost:3000/api/notes/REPLACE_WITH_REAL_ID -H "Content-Type: application/json" -d '{"title":"Updated title","body":"New text","tags":["updated"]}'
```

Response **200**: updated note object (with updated `updatedAt`). PUT requires `title`; omitted `body` and `tags` are replaced with `""` and `[]`. It does not modify `_id` or `createdAt`. Missing note returns **404**.

### 5. Delete — DELETE /api/notes/:id

```bash
curl -i -X DELETE http://localhost:3000/api/notes/REPLACE_WITH_REAL_ID
```

Response **204 No Content**, with an **empty response body**. Deleting the same ID again returns **404** `{"error":"Note not found"}`.

## Error handling

All errors have JSON `{ "error": "meaningful message" }`, except successful DELETE (204, no body). Invalid input, unexpected fields, a non-object body, bad ObjectIDs, and malformed JSON return **400**. Missing note or unknown route returns **404**. Unexpected server/database failures return **500** with a generic message (details are logged on the server). If the initial database connection fails, startup exits clearly rather than serving a broken API.

## End-to-end database test (required before submission)

1. Start the server with a working MongoDB connection.
2. POST a note; save its `_id` from the response.
3. GET the list; confirm it appears.
4. GET `/:id`; confirm its contents.
5. PUT `/:id`; GET it again and confirm the update.
6. **Stop and restart the server**. GET `/:id` again: the updated note must still exist (proves persistence beyond a JavaScript array).
7. DELETE `/:id` and confirm status 204; GET it again and confirm 404.
8. Test POST without title, GET with invalid ID, and a malformed JSON body; all must return 400 without crashing the server.

The Postman collection contains labeled requests for both success and error cases. Create a note first so the collection can record its ID for later requests.
